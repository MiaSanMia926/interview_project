## 一、后端修改

### 1. `backend/main.py` — Windows GBK 编码修复


**原因**：emoji 字符（✅📊👋）在 Windows GBK 编码下触发 `UnicodeEncodeError`，导致 FastAPI 启动失败。

### 2. `backend/services/user_service.py` — 用户"获取或创建"

```diff
  def create_user(self, username: str) -> User:
-     """创建用户"""
+     """获取或创建用户（与前端 Express 版行为保持一致）"""
      existing = self.db.query(User).filter(User.username == username).first()
      if existing:
-         raise ValueError("用户名已存在")
+         return existing
```

**原因**：原逻辑为"仅创建"，已存在则抛异常。前端硬编码 `userId: 'default-user'`，但 Express 版是"获取或创建"。改为查找已存在用户并直接返回，与 Express 版行为一致。

### 3. `backend/services/interview_service.py` — 并行题目生成 + 列表字段

#### 3a. `start_interview` 并行化

```diff
- # 串行生成
- for idx in range(MAX_QUESTIONS):
-     interview.current_question_index = idx
-     try:
-         self._generate_question(interview)
-     except Exception:
-         self._generate_fallback_question(interview)

+ # 并行生成
+ from concurrent.futures import ThreadPoolExecutor, as_completed
+ def generate_one(idx: int) -> Question:
+     from ..database import SessionLocal
+     db = SessionLocal()
+     try:
+         local_interview = db.query(Interview).filter(...).first()
+         ...
+     finally:
+         db.close()
+
+ with ThreadPoolExecutor(max_workers=MAX_QUESTIONS) as executor:
+     futures = {executor.submit(generate_one, idx): idx for idx in range(MAX_QUESTIONS)}
+     for future in as_completed(futures):
+         questions.append(future.result())
```

**原因**：3 道题串行调用 LLM 需约 120 秒，前端 20 秒超时直接失败。改为 `ThreadPoolExecutor` 并行生成，总耗时降至约 20 秒。

#### 3b. 新增 session 参数版本方法

- `_generate_question_in_session(interview, db)` — 接受外部 session
- `_generate_fallback_question_in_session(interview, db)` — 同上

原因：多线程环境下每个线程需要独立的数据库 session，不能共享 `self.db`。

#### 3c. `list_interviews` 返回 techStack

```diff
  "items": [{
      "id": i.id,
      ...
+     "tech_stack": json.loads(i.tech_stack) if i.tech_stack else [],

  }]
```

**原因**：前端 HomeView 历史列表渲染需要 `interview.techStack`，之前缺失导致技术栈标签不显示。

## 二、前端修改

### 6. `frontend/src/api/client.ts` — 三项关键修改

#### 6a. 超时时间调整


#### 6c. getHistory 兼容分页响应

```diff
- getHistory: () => request<Interview[]>('/api/interviews'),
+ getHistory: async () => {
+     const data = await request<InterviewListResponse>('/api/interviews');
+     // FastAPI 后端返回分页格式 {total, page, size, items}，提取 items 数组
+     if (data && Array.isArray((data as any).items)) {
+       return (data as InterviewListResponse).items;
+     }
+     // 兼容 Express 版直接返回数组的情况
+     return data as unknown as Interview[];
+ },
```

**原因**：FastAPI 后端返回 `{ total, page, size, items: [...] }` 分页格式，但前端期望纯数组 `Interview[]`。不提取会导致 `historyInterviews` 变成对象而非数组，`v-for` 遍历行为异常，且 `historyInterviews.length` 为 `undefined`。

### 8. `frontend/src/components/InterviewView.vue` — 异步题目渲染

```diff
- onMounted(() => {
-   if (questions.value.length > 0 && messages.value.length === 0) {
-     messages.value = [{ id: 'msg-start', ... }];
-   }
- });
+ let openingRendered = false;
+ function tryRenderOpening() {
+   if (openingRendered) return;
+   if (questions.value.length === 0) return;
+   openingRendered = true;
+   messages.value = [{ id: 'msg-start', ... }];
+ }
+ onMounted(() => tryRenderOpening());
```

**原因**：`App.vue` 先切换 tab 到 InterviewView（此时 `questions: []`），再调 `startInterview` API 异步拿到题目。`onMounted` 在题目到达前已执行完毕，导致开幕消息永远不渲染，面试界面显示空白。

## 三、架构说明

```
浏览器 (localhost:3003)
  │
  ├─ 页面加载 → Express + Vite → 返回 Vue SPA
  │
  └─ API 请求 → http://localhost:8000 → FastAPI 后端
       ├─ POST /api/users           → 获取或创建用户
       ├─ GET  /api/interviews       → 面试列表（分页）
       ├─ POST /api/interviews       → 创建面试
       ├─ POST /api/interviews/{id}/start  → 并行生成 3 道题（~20s）
       ├─ POST /api/interviews/{id}/answer → 提交回答 + 追问/评估
       ├─ GET  /api/interviews/{id}/summary → 面试总结
       ├─ GET  /api/users/{id}/profile → 用户能力画像
       └─ POST /api/positions/suggest → 职位推荐
```
