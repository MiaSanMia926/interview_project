## 一、工作总览

本次后端工作围绕**"从原型 stub 转为可交付的工程实现"**展开，共 5 大块：

| 模块 | 工作内容 | 对应代码 |
|------|---------|---------|
| ① 前后端打通 | 把 Vue 前端真正切到 FastAPI，统一 API 契约 | `routes/interviews.py`、`schemas/interview.py`、`services/interview_service.py`、`frontend/src/api/client.ts` |

## 二、核心改造详解

### 1. 前后端打通（API 契约统一）

#### 问题背景
原 `start` 接口每次只生成 1 道题、返回 `AnswerResponse`；但前端 `InterviewView` 的侧边栏题目进度、雷达图完成度都依赖 `interview.questions[]` 数组（一次性 3 题）。`submitAnswer` 也丢失了前端传来的 `questionId`。

#### 关键改动

**① `start_interview` 改为一次性生成全部题目**

`backend/services/interview_service.py`：
```python
def start_interview(self, interview_id: str) -> Interview:
    """一次性生成 MAX_QUESTIONS 道题"""
    interview = ...
    for idx in range(MAX_QUESTIONS):
        interview.current_question_index = idx
        try:
            self._generate_question(interview)   # 调 Agent 生成
        except Exception:
            self._generate_fallback_question(interview)  # 兜底占位
    interview.status = "in_progress"
    ...
    return interview   # 返回 ORM 对象，由 response_model 自动序列化
```

- 路由层 `response_model` 从 `AnswerResponse` 改为 `InterviewResponse`
- 前端拿到的就是含完整 `questions[]` 的对象

**② `submit_answer` 接受 `questionId` 精确定位题目**

`schemas/interview.py`：
```python
class AnswerSubmit(CamelModel):
    question_id: Optional[str] = Field(None, alias="questionId")
    user_answer: str = Field(..., alias="userAnswer", min_length=1)
```

`interview_service.py` 的 `_get_current_question` 支持按 id 优先查找，回退到 index：
```python
def _get_current_question(self, interview, question_id=None):
    if question_id:
        q = self.db.query(Question).filter(
            Question.id == question_id, Question.interview_id == interview.id
        ).first()
        if q:
            return q
    # 回退：按 index 取
    ...
```

**③ `InterviewResponse` 加嵌套 `QuestionInfo`**

为了让 Pydantic 能正确序列化 ORM 关系对象：
```python
class QuestionInfo(CamelModel):
    id: str
    interview_id: Optional[str] = Field(None, alias="interviewId")
    question_text: str = Field(alias="questionText")
    ...
    class Config:
        from_attributes = True   # 关键：从 ORM 对象读字段
```

#### 可演示点
- 启动后端，调用 `POST /api/interviews/{id}/start`，返回 JSON 里 `questions` 数组有 3 项
- 提交回答时携带 `questionId`，后端日志能看到精确命中对应题目

### 2. Agent/RAG 真实接入（最大工作量）

#### 问题背景
原 `_generate_question` 是写死的 5 条占位题，`_evaluate_answer` 永远返回 75 分，`_decide_next` 追问文案写死"能详细说说吗？"——全是 TODO stub。

#### 关键改动

**① 懒初始化 + 全局单例**

`interview_service.py` 顶部：
```python
_INTERVIEWER = None
_EVALUATOR = None

def _get_interviewer():
    """首次用到时才实例化，避免启动时强制要 Key"""
    global _INTERVIEWER
    if _INTERVIEWER is None:
        try:
            from agents.interviewer import InterviewerAgent
            _INTERVIEWER = InterviewerAgent()
        except Exception:
            _INTERVIEWER = False   # sentinel 标记不可用
    return _INTERVIEWER if _INTERVIEWER else None
```

**好处**：
- 后端启动时不强制要求 LLM Key（无 Key 也能跑，走 fallback）
- 同一个 Agent 实例被整场面试复用，不重复初始化

**② 出题接入真实 Agent + RAG**

```python
def _generate_question(self, interview):
    tech_stack = json.loads(interview.tech_stack) if interview.tech_stack else []
    first_tech = tech_stack[0] if tech_stack else "技术"

    ...
```

**③ 评估接入真实 Agent**


`_decide_next` 里：

### 3. ⭐ LCEL 管道接入（重点答辩项）

#### 问题背景
考核标准明确："**仅裸调用 LLM 接口、未搭建 LCEL 管道，后端总分上限 22 分**"。原 `agents/base.py` 只有 `self.llm.invoke()`，没有 `prompt | llm | parser` 管道写法。

#### 关键改动

**① `BaseAgent` 新增 LCEL 管道基础设施**

`agents/base.py`：
```python
from langchain_core.runnables import RunnableSequence
from langchain_core.output_parsers import StrOutputParser, JsonOutputParser

class BaseAgent:
    def __init__(self, ...):
        ...
        self._str_parser = StrOutputParser()

    def _build_chain(self, prompt, parser=None) -> RunnableSequence:
        """构建 LCEL 管道：prompt | llm | parser"""
        if parser is None:
            parser = self._str_parser
        return prompt | self.llm | parser

    def _invoke_chain(self, chain, inputs, *, retry=True):
        """调用 LCEL 管道（带指数退避重试）"""
        if not retry:
            return chain.invoke(inputs)
        for attempt in range(MAX_RETRIES + 1):
            try:
                return chain.invoke(inputs)
            except Exception as e:
                if attempt < MAX_RETRIES and _is_retryable(e):
                    time.sleep(BASE_DELAY_SECONDS * (2 ** attempt))
                    continue
                raise
```

**② `InterviewerAgent` 出题/追问改用 LCEL**

```python
def generate_question(self, target_company, target_position, tech_stack, question_index, previous_qa):
    ...
    # 构建 LCEL 管道
    chain = self._build_chain(self.question_prompt, self._str_parser)
    question = self._invoke_chain(chain, {
        "target_company": target_company,
        "target_position": target_position,
        "tech_stack": "、".join(tech_stack),
        ...
    })
    return self._strip_quotes(question)
```

**③ `EvaluatorAgent` 用 LCEL + JsonOutputParser**

```python
class EvaluatorAgent(BaseAgent):
    def __init__(self, ...):
        super().__init__(temperature=0.3)
        self._json_parser = JsonOutputParser()   # 直接解析成 dict

    def evaluate(self, question, user_answer, ...):
        chain = self._build_chain(self.evaluate_prompt, self._json_parser)
        parsed = self._invoke_chain(chain, {
            "question": question,
            "user_answer": user_answer,
            ...
        })
        if isinstance(parsed, dict) and parsed.get("score") is not None:
            return self._result_to_dict(self._dict_to_result(parsed))
        # 兜底：文本提取
        ...
```

#### 答辩要点（防止被问倒）

| 可能被问到的问题 | 回答 |
|----------------|------|
| "你的 LCEL 管道在哪？" | `agents/base.py` 的 `_build_chain`，被 `interviewer.py` 和 `evaluator.py` 的主方法调用 |
| "怎么证明是真管道不是包装？" | `_build_chain` 返回的是 `RunnableSequence`，`chain.steps` 是 `[ChatPromptTemplate, ChatOpenAI, StrOutputParser]` 三段 |
| "JsonOutputParser 用在哪？" | `EvaluatorAgent.evaluate`，模型输出直接解析成 dict，省去手写正则提取 JSON |
| "为什么不直接写在路由里？" | 关注点分离：路由只管 HTTP，业务逻辑在 service，LLM 调用在 agent，管道复用通过基类 |
| "管道能组合吗？" | 能，`RunnableSequence` 本身是 Runnable，可以用 `\|` 继续接其它 Runnable |

### 4. 工程健壮性改造

#### ① 重试与降级
- `_invoke_chain` 对 `APITimeoutError`、`RateLimitError`、`APIConnectionError`、`InternalServerError` 做指数退避（1s → 2s → 4s，最多 3 次）
- 4xx 错误不重试，直接抛出

#### ② Key 解耦
- `KnowledgeAgent` 不再继承 `BaseAgent`，纯本地 RAG 检索不需要 LLM Key：
```python
class KnowledgeAgent:
    """纯本地RAG检索，不调用LLM，不需要API Key"""
    def __init__(self):
        self._rag_engine = None
        try:
            from rag.engine import RAGEngine
            self._rag_engine = RAGEngine()
        except ImportError:
            self._rag_engine = None
```

#### ③ CORS 修正
```python
# 之前（不安全 + 浏览器禁止）
allow_origins=["*"], allow_credentials=True

# 现在
allow_origins=["http://localhost:3003"], allow_credentials=True
```

#### ④ async 阻塞修复
所有路由从 `async def` 改为 `def`，FastAPI 自动丢进线程池，避免同步 SQLAlchemy 和 `time.sleep` 阻塞事件循环。

#### ⑤ 依赖补全
`requirements.txt` 新增：
```
langchain-openai>=0.1.0
langgraph>=0.2.0
openai>=1.0.0
pytest>=7.0.0
httpx>=0.24.0
```

#### ⑥ 日志路径绝对化
```python
_PROJECT_ROOT = os.path.dirname(os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
_DEFAULT_LOG_DIR = os.path.join(_PROJECT_ROOT, "data", "logs")
```
不管从哪个 cwd 启动，日志都写到正确位置。

#### ⑦ `datetime.utcnow()` 弃用修复
全部改为 `datetime.now(timezone.utc)`，消除 Python 3.12+ 的 `DeprecationWarning`。
